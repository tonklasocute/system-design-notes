# บทที่ 9: ออกแบบ Web Crawler (Design a Web Crawler)

## บทนำ
**Web crawler** หรือที่รู้จักกันในชื่อ spider หรือ robot คือระบบที่ใช้ในการค้นหาและรวบรวมเนื้อหาบนเว็บ เช่น หน้าเว็บ (web pages), รูปภาพ, และวิดีโอ บทนี้จะเน้นการออกแบบ web crawler ที่สามารถขยายตัวได้ (scalable) สำหรับใช้ทำ **การจัดทำดัชนีของเสิร์ชเอนจิน (search engine indexing)**

### การใช้งานของ Web Crawler (Applications of Web Crawlers)
1. **การจัดทำดัชนีของเสิร์ชเอนจิน (Search Engine Indexing):** รวบรวมหน้าเว็บเพื่อสร้างดัชนีที่สามารถค้นหาได้ (เช่น Googlebot)
2. **การเก็บบันทึกเว็บ (Web Archiving):** เก็บรักษาข้อมูลเว็บไว้ใช้งานในอนาคต (เช่น US Library of Congress)
3. **การทำ Web Mining:** สกัดความรู้จากข้อมูลบนเว็บ (เช่น การวิเคราะห์ทางการเงินจากรายงานผู้ถือหุ้น)
4. **การเฝ้าติดตามเว็บ (Web Monitoring):** ตรวจจับการละเมิดลิขสิทธิ์หรือเครื่องหมายการค้า

### ความท้าทายในการออกแบบ (Design Challenges)
web crawler ที่ดีต้องรับมือกับ:
- **ความสามารถในการขยายตัว (Scalability):** รองรับหน้าเว็บนับพันล้านหน้าด้วยการทำงานแบบขนาน (parallelization)
- **ความทนทาน (Robustness):** จัดการกับ HTML ที่ผิดพลาด, การล่ม (crash), และลิงก์ที่เป็นอันตราย
- **ความสุภาพ (Politeness):** หลีกเลี่ยงการส่ง request จำนวนมากเกินไปจนทำให้เซิร์ฟเวอร์ปลายทางรับภาระหนักเกินไป
- **ความสามารถในการขยายฟีเจอร์ (Extensibility):** รองรับประเภทเนื้อหาใหม่ ๆ โดยแก้ไขระบบให้น้อยที่สุด

## ขั้นตอนที่ 1: ทำความเข้าใจปัญหา (Understanding the Problem)

### ข้อกำหนด (Requirements)
1. Crawl หน้าเว็บ **1 พันล้านหน้าต่อเดือน** (400 หน้า/วินาที ช่วงพีค 800 QPS)
2. รวบรวม **เนื้อหาแบบ HTML เท่านั้น**
3. ติดตามหน้าเว็บที่สร้างใหม่และที่มีการอัปเดต
4. ไม่นับรวมเนื้อหาที่ซ้ำกัน (duplicate content)
5. จัดเก็บข้อมูลที่ crawl มาได้เป็นเวลา **5 ปี** ซึ่งต้องใช้พื้นที่จัดเก็บประมาณ 30 PB

## ขั้นตอนที่ 2: การออกแบบระดับสูง (High-Level Design)

### คอมโพเนนต์ (Components)

</p>

1. **Seed URLs:** จุดเริ่มต้นสำหรับ crawler
    - จำเป็นต้องเลือกอย่างมีชั้นเชิงเพื่อให้เป็นจุดเริ่มต้นที่ดีที่ crawler สามารถใช้ในการไล่ตามลิงก์ต่าง ๆ ได้มากที่สุด
    - สามารถเลือกตามความนิยมของเว็บไซต์ในแต่ละพื้นที่ หรือเลือกตามหัวข้อ (topic)
    - กลยุทธ์: จัดกลุ่มตามพื้นที่ (locality) หรือหัวข้อ (เช่น กีฬา, สุขภาพ)

2. **URL Frontier:** จัดเก็บ URL ที่รอการดาวน์โหลด
   - ถูก implement เป็น **FIFO queue**

3. **HTML Downloader:** ดาวน์โหลดหน้าเว็บจาก URL ที่ URL Frontier จัดเตรียมไว้ให้

4. **DNS Resolver:** แปลง URL ให้เป็น IP address

5. **Content Parser:** ตรวจสอบความถูกต้องและแยกวิเคราะห์ (parse) หน้าเว็บ
   - ทิ้งหน้าเว็บที่มีรูปแบบไม่ถูกต้อง (malformed)

6. **Content Seen?:** ตรวจสอบเนื้อหาที่ซ้ำกันโดยเปรียบเทียบค่า hash (เปรียบเทียบค่า hash ของหน้าเว็บสองหน้า)

7. **Content Storage:** จัดเก็บหน้าเว็บ HTML ไว้บนดิสก์ (เนื้อหาที่ได้รับความนิยมจะถูกเก็บไว้ในหน่วยความจำเพื่อลด latency)

8. **URL Extractor:** สกัดลิงก์ใหม่ ๆ จากหน้าเว็บที่ถูก parse แล้ว

9. **URL Filter:** ตัดทิ้ง URL ที่อยู่ใน blacklist หรือที่มีข้อผิดพลาด

10. **URL Seen?:** ติดตาม URL ที่เคยเข้าเยี่ยมชมแล้ว เพื่อหลีกเลี่ยงความซ้ำซ้อน

11. **URL Storage:** จัดเก็บ URL ที่เคยเข้าเยี่ยมชมแล้ว


---

### ลำดับการทำงาน (Workflow)
1. เพิ่ม **Seed URLs** เข้าไปใน URL Frontier
2. **HTML Downloader** ดึงข้อมูลจาก URL และแปลง IP ผ่าน DNS Resolver
3. **Content Parser** ตรวจสอบความถูกต้องและส่งเนื้อหาต่อไปยังคอมโพเนนต์ "Content Seen?"
4. หากเนื้อหาเป็นของใหม่ ให้สกัดลิงก์ผ่าน **URL Extractor**
5. กรองและเพิ่มลิงก์ที่ไม่ซ้ำกันเข้าไปใน URL Frontier

## ขั้นตอนที่ 3: เจาะลึกคอมโพเนนต์สำคัญ (Deep Dive into Key Components)
### DFS/BFS
-  เว็บสามารถมองได้เป็นกราฟแบบมีทิศทาง (directed graph) โดยที่หน้าเว็บคือ node และ hyperlink (URL) คือ edge
-  โดยทั่วไปจะใช้ BFS ในการไล่สำรวจกราฟ (graph traversal) เนื่องจากความลึกอาจมีมากจนเกินไป ทำให้ DFS ไม่เหมาะสม
-  BFS แบบมาตรฐานไม่ได้คำนึงถึงลำดับความสำคัญ (priority) ของ URL เพราะไม่ใช่ทุกหน้าเว็บที่มีคุณภาพและความสำคัญเท่ากัน


### URL Frontier
- **ความสุภาพ (Politeness):**
    - ต้องมั่นใจว่ามีเพียง request เดียวต่อ host ในเวลาเดียวกัน โดยเพิ่มดีเลย์ (delay) ระหว่างงานดาวน์โหลดสองงาน
    - ใช้การ mapping จากชื่อ host ไปยัง queue และ worker (download) thread
    - แต่ละ downloader thread จะมี FIFO queue แยกต่างหาก และจะดาวน์โหลด URL จาก queue นั้นเท่านั้น

        <img src="./images/politeness.png" alt="Politeness" width="500">

    - **Queue router:** ทำหน้าที่ให้แน่ใจว่าแต่ละ queue (b1, b2, … bn) มีเพียง URL จาก host เดียวกันเท่านั้น
    - **Mapping table:** ทำการ map แต่ละ host ไปยัง queue ที่เกี่ยวข้อง
    - **Queue selector:** worker thread แต่ละตัวถูก map เข้ากับ FIFO queue หนึ่งตัว และจะดาวน์โหลด URL จาก queue นั้นเท่านั้น ตรรกะการเลือก queue ดำเนินการโดย Queue selector
    - **Worker thread 1 ถึง N:** worker thread จะดาวน์โหลดหน้าเว็บจาก host เดียวกันตามลำดับ (sequentially) และสามารถเพิ่มดีเลย์ระหว่างงานดาวน์โหลดสองงานได้

- **ลำดับความสำคัญ (Priority):**
    - กำหนดลำดับความสำคัญที่สูงกว่าให้กับหน้าเว็บที่สำคัญ (เช่น ตาม PageRank หรือความถี่ในการอัปเดต)

        <img src="./images/prioritizer.png" alt="Politeness" width="500">

    - **Prioritizer:** รับ URL เป็น input และคำนวณลำดับความสำคัญ
    - **Queue f1 ถึง fn:** แต่ละ queue จะมีลำดับความสำคัญที่กำหนดไว้ queue ที่มีลำดับความสำคัญสูงจะถูกเลือกด้วยความน่าจะเป็นที่สูงกว่า
    - **Queue selector:** เลือก queue แบบสุ่มโดยเอนเอียง (bias) ไปทาง queue ที่มีลำดับความสำคัญสูงกว่า
    - **Front queues:** จัดการเรื่องลำดับความสำคัญ (prioritization)
    - **Back queues:** จัดการเรื่องความสุภาพ (politeness)

- **ความสดใหม่ของข้อมูล (Freshness):** ทำการ recrawl ตามประวัติการอัปเดตหรือความสำคัญของหน้าเว็บ


### HTML Downloader
- **การปฏิบัติตาม Robots.txt (Robots.txt Compliance):** เคารพกฎที่กำหนดไว้ในไฟล์ robots.txt
- **การปรับปรุงประสิทธิภาพ (Performance Optimizations):**
  1. ทำการ crawl แบบกระจาย (distributed) โดยใช้เซิร์ฟเวอร์หลายตัว
  2. ใช้ **DNS cache** เพื่อหลีกเลี่ยงการ lookup ซ้ำ ๆ
  3. กระจาย crawl server ไปตามพื้นที่ทางภูมิศาสตร์ต่าง ๆ เพื่อให้ดาวน์โหลดได้เร็วขึ้น
  4. ใช้ timeout ที่สั้น เพื่อหลีกเลี่ยงเซิร์ฟเวอร์ที่ทำงานช้าหรือไม่ตอบสนอง

### ความทนทาน (Robustness)
1. **Consistent Hashing:** กระจายโหลดไปยังเซิร์ฟเวอร์ต่าง ๆ ได้อย่างมีประสิทธิภาพ
2. **การจัดการข้อผิดพลาด (Error Handling):** ป้องกันไม่ให้ระบบล่มจาก exception
3. **การตรวจสอบความถูกต้องของข้อมูล (Data Validation):** รักษาความสมบูรณ์ของเนื้อหา

### ความสามารถในการขยายฟีเจอร์ (Extensibility)
- เพิ่มโมดูลสำหรับประเภทเนื้อหาใหม่ ๆ (เช่น PNG downloader, web monitor)
- ตัวอย่าง: เสียบโมดูลสำหรับเฝ้าติดตามเนื้อหาบนเว็บเพื่อตรวจจับการละเมิดลิขสิทธิ์

### การหลีกเลี่ยงเนื้อหาที่เป็นปัญหา (Avoiding Problematic Content)
1. **เนื้อหาที่ซ้ำกัน (Duplicate Content):** ตรวจจับด้วยการเปรียบเทียบค่า hash
2. **Spider Traps:** หลีกเลี่ยงการวนลูปไม่สิ้นสุดด้วยเทคนิคต่าง ๆ เช่น การจำกัดความยาวของ URL
3. **สัญญาณรบกวนของข้อมูล (Data Noise):** กรองเนื้อหาที่ไม่เกี่ยวข้อง เช่น โฆษณาหรือสแปม

## ขั้นตอนที่ 4: สรุปจบ (Wrap Up)
### สิ่งสำคัญที่ควรจำ (Key Takeaways)
1. Web crawler ต้องรักษาสมดุลระหว่างความสามารถในการขยายตัว, ความทนทาน, ความสุภาพ, และความสามารถในการขยายฟีเจอร์
2. **ความสุภาพ (Politeness)** ป้องกันไม่ให้เซิร์ฟเวอร์ทำงานหนักเกินไป ในขณะที่ **ลำดับความสำคัญ (priority)** ช่วยให้หน้าเว็บที่สำคัญถูก crawl ก่อน
3. การจัดเก็บข้อมูลอย่างมีประสิทธิภาพและการจัดการข้อผิดพลาดเป็นสิ่งสำคัญมากสำหรับการ crawl ในระดับขนาดใหญ่

### ประเด็นเพิ่มเติมที่ต้องพิจารณา (Additional Considerations)
- **การ Render ฝั่งเซิร์ฟเวอร์ (Server-Side Rendering):** จัดการกับเนื้อหาแบบไดนามิกที่สร้างขึ้นโดย JavaScript หรือ AJAX
- **มาตรการป้องกันสแปม (Anti-Spam Measures):** ตัดหน้าเว็บที่มีคุณภาพต่ำหรือไม่เกี่ยวข้องออกไป
- **การทำ Database Sharding:** ขยายชั้นข้อมูล (data layer) ด้วยการทำ replication และ sharding
- **การขยายแนวนอน (Horizontal Scaling):** ใช้เซิร์ฟเวอร์แบบ stateless เพื่อขยายงาน crawl ได้อย่างมีประสิทธิภาพ
- **การวิเคราะห์ข้อมูล (Analytics):** รวบรวมและวิเคราะห์ข้อมูลเพื่อให้ได้ข้อมูลเชิงลึก
